## 2. 合约层设计

### 2.1 AgentPayAccount（限额智能账户，核心）

```
AccountPolicy {
    budget (uint256)           // 总预算 (USDC, 6位小数)
    spent (uint256)            // 已消费
    merchantWhitelist (mapping(address => bool))
    perTxMax (uint256)         // 单笔上限
    expiresAt (uint64)         // TTL
    paused (bool)
}

关键函数:
- createAccount(policy)        // 工厂方法, 一Agent一账户
- authorizePayment(merchant, amount, nonce, sig)  // Agent session key 签名
- checkLimits(merchant, amount) → (bool, reason)  // 预算/白名单/单笔/TTL
- topUp(amount) / revoke()     // owner 注资/吊销
```

- Agent 拿不到账户托管资金，只能"请求授权支付"
- 四重限制全部合约内校验：预算余额、商户白名单、单笔上限、TTL
- revoke() 即时冻结——比信用卡挂失还快

### 2.2 FacilitatorSettlement（结算合约）

```
- settle(accountAddr, merchant, amount, nonce, sig)
    验证: signature有效 + nonce未用 + account.checkLimits通过
    执行: USDC account→merchant
    写入: ReceiptsRegistry.log(...)
    防重放: nonce 记录
```

- 开源参考实现，商户可自部署或用公共实例
- 与 x402 官方规范对齐（EIP-3009 transferWithAuthorization 风格签名）

### 2.3 ReceiptsRegistry（收据注册表）

```
Receipt {
    accountAddr (address)
    merchant (address)
    amount (uint256)
    resourceHash (bytes32)    // 所购数据/服务的内容hash
    timestamp (uint64)
    settlementTx (bytes32)
}
- log() 仅限已注册 settlement 合约调用
- verify(receiptId) view 供面板/第三方验证
```

- 资源 hash 让收据可核对："付了钱, 数据没给" 有据可查
- 商户信誉可由历史收据推导（未来扩展：商户评分）

## 3. x402 支付闭环

```
1. Agent → GET 商户API
2. 商户 ← 402 { price: $0.01 USDC, facilitator: 0xSettlement }
3. Agent 签名支付凭证 (账户session key)
4. Facilitator 验证 → FacilitatorSettlement.settle() → 链上结算
5. 商户收到 settlement proof → 200 { data }
6. Registry 收据自动生成
```

- 支付凭证 = EIP-712 结构化签名（商户/金额/nonce/期限），防篡改防重放
- 商户只需监听链上 settle 事件即可确认收款（无需信任 facilitator）

## 4. 安全模型

| 威胁 | 防御 |
|------|------|
| Agent key 泄露 | 损失上限=预算余额；owner revoke 冻结 |
| 支付凭证重放 | nonce + 截止时间 |
| 恶意 facilitator | 商户链上事件自证，facilitator 无法卷款 |
| Agent 超支 | perTxMax + budget 合约硬限制 |
| 商户收款不发货 | resourceHash 收据可对证 |
