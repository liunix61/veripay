# VeriPay 核心流程（Core Flows）

> 创建：2026-09-13 | 配套：01-总体方案 / 02-系统架构 / 03-技术框架

---

## 流程 1：创建 Agent 支付账户

```
开发者                        AgentPayAccount 工厂
  │ 1. 定义 policy: 预算$5 / 白名单[CMC] / 单笔≤$0.5 / TTL 48h
  │ 2. createAccount(policy) ──→ 账户地址 + 绑定 Agent session key
  │ 3. topUp($5 USDC) ────────→ 预算就位
```

- 一 Agent 一账户，账户间完全隔离
- 政策修改走 owner + 重新部署账户（简单模型，不给 Agent 留后门）

## 流程 2：x402 付费调用（核心闭环）

```
Agent引擎              商户API              Facilitator           合约
────────              ────────             ───────────           ────
GET /signal?NVDA
              ←──402 {price:$0.01, settlement:0x…, dataHash}
签名 PaymentAuth(EIP-712)
POST /settle(auth, sig) ──────────────────→ 验签+eth_call限额
                                            settle() ──────────→ USDC 转账
                                                                  + 收据写入
              ←──200 {data, receiptId} ←── 返回receiptId
数据+receiptId → 引擎日志 & 面板展示
```

**时序保证**：先结算后发货（商户看链上事件再放行数据）；商户不发货时 resourceHash 收据可对证。

## 流程 3：限额拒绝场景

| 场景 | 检测点 | 返回 reason | Agent 行为 |
|------|--------|------------|-----------|
| 商户不在白名单 | checkLimits #3 | NOT_WHITELISTED | 放弃该调用 |
| 单笔超上限 | checkLimits #4 | TX_TOO_LARGE | 拆分或降级 |
| 预算耗尽 | checkLimits #5 | BUDGET_EXHAUSTED | 通知用户充值或停止 |
| TTL 过期 | checkLimits #1 | EXPIRED | 停止付费调用 |
| 已吊销 | checkLimits #2 | REVOKED | 立即停止 |

所有拒绝在链下 eth_call 阶段即可预知——Facilitator /verify 先行校验，不浪费 gas。

## 流程 4：用户审计与控制

```
用户面板:
- 实时流水: 时间/商户/金额/资源描述 (来自收据事件)
- 预算余量: budget - spent (链上实时读取)
- 一键 revoke: 账户即时冻结
- 收据验证: receiptId → verify() → 链上自证
```

## 流程 5：商户接入

```
1. 注册: 部署/登记 merchant 地址
2. 改造API: 中间件检查 402 (paywall(verify_url, price) 一行)
3. 收款: 监听 Settlement.settle 事件 → 发货
4. 对账: ReceiptsRegistry 历史查询
```

商户无需信任 facilitator——链上事件即收款证明。

## 异常分支

| 异常 | 处理 |
|------|------|
| settle 成功但商户未发货 | 收据在, resourceHash 可对证, 用户可申诉/吊销 |
| Facilitator 宕机 | 商户可自托管; 支付凭证本身链上有效, 换服务继续 |
| Agent key 泄露 | revoke + 损失≤预算余额 |
| 主网 gas 波动 | L2 成本天然低, 预留 2x buffer |
