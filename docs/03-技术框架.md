## 2. 技术栈

| 组件 | 选型 | 说明 |
|------|------|------|
| 合约 | Solidity ^0.8.24 + Foundry | 自定义错误 + fuzz |
| 稳定币 | USDC（Arbitrum One 官方原生） | 6 位小数 |
| 签名 | EIP-712 结构化签名 | 支付凭证：merchant/amount/nonce/deadline |
| 转账授权 | EIP-3009 transferWithAuthorization 模式 | 与 x402 规范对齐 |
| Facilitator | FastAPI 开源服务 | 商户可自托管或用公共实例 |
| 前端 | Nuxt4 + viem | 与 VeriAgent 共享组件 |
| 测试 | forge + pytest + anvil fork 主网 | 主网 fork 验证真实 USDC 行为 |

## 3. 合约关键接口

```solidity
// AgentPayAccount.sol
function createAccount(AccountPolicy calldata p) external returns (address account);
function authorizePayment(address merchant, uint256 amount, uint256 nonce,
                           uint256 deadline, bytes calldata sig) external;
function checkLimits(address merchant, uint256 amount)
        external view returns (bool ok, bytes32 reason);
function topUp(address account, uint256 amount) external;   // owner
function revoke(address account) external;                  // owner 即时冻结

// FacilitatorSettlement.sol
function settle(address account, address merchant, uint256 amount,
                uint256 nonce, uint256 deadline, bytes calldata sig)
        external returns (bytes32 receiptId);
function registerFacilitator(address f) external;           // owner 治理

// ReceiptsRegistry.sol
function log(address account, address merchant, uint256 amount,
             bytes32 resourceHash) external returns (uint256 receiptId);
function verify(uint256 receiptId) external view returns (Receipt memory);
```

## 4. 限额校验顺序（AgentPayAccount 核心）

1. **TTL**：`block.timestamp < expiresAt`
2. **暂停**：`!paused && !revoked`
3. **白名单**：`merchantWhitelist[merchant]`
4. **单笔上限**：`amount ≤ perTxMax`
5. **预算余额**：`spent + amount ≤ budget`

任一失败 revert(reason)，Agent 端收到 reason 自修正或放弃。

## 5. EIP-712 支付凭证结构

```solidity
PaymentAuth(
    address account,
    address merchant,
    uint256 amount,
    uint256 nonce,
    uint256 deadline
)
// domain: {name: "VeriPay", version: "1", chainId: 1, verifyingContract: Settlement}
```

- 域分隔含 chainId + 合约地址 → 跨链/跨合约重放不可能
- nonce 按账户递增记录，deadline 防凭证长期有效

## 6. Facilitator 服务

```
POST /verify  {paymentAuth, sig} → 验签 + 模拟 checkLimits (eth_call)
POST /settle  {paymentAuth, sig} → 发送 settle 交易 → 返回 receiptId + txHash
GET  /receipt/{id}               → 读链上收据
```

- 商户 SDK：3 行接入（`paywall(verify_url, price)` 装饰器）
- Facilitator 本身无需被信任：结算上链，商户看事件收款

## 7. 测试策略

| 层 | 内容 |
|----|------|
| forge 单测 | 限额 5 条规则各自拒绝路径 + 正常支付 + nonce 防重放 |
| forge fuzz | 金额/时间/nonce 边界 |
| 攻击 PoC | 凭证重放 / 越权商户 / 超支 / TTL 过期后支付 |
| pytest | Facilitator API + 商户 SDK |
| anvil fork | 主网 fork + 真实 USDC 合约全链路 |

## 8. Gas 预算（Arbitrum One）

| 操作 | 预估 gas | 成本(~$0.50/gas价折算) |
|------|---------|----------------------|
| settle() | ~150k | <$0.01 |
| createAccount() | ~200k | <$0.01 |
| log() | ~60k | ~$0.003 |

**$0.01 级微支付在经济上成立**——这是本项目的核心论证。
